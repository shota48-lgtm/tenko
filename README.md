# tenko

チャットと勤怠を繋いだオフィスアプリ。

出勤する場所そのものを仮想オフィス化し、勤怠・現在の状態・チーム内のやり取りを一つの場所で完結させることを目指す。
チャットでの発言から勤怠の下書きを立て、**確定は必ず人間が押す。** 機械は下書きまでしか作らない。

詳しい方針と経緯は `docs/TENKO_STATE.md` にある。

## 動かし方

```bash
# 1) WebSocket サーバー（在席状態と通知を配る。ポート 8080）
node ws-server/index.js

# 2) アプリ本体（ポート 3000）
npm run dev
```

`.env.local` に `DATABASE_URL`（Neon の接続文字列）が必要。

| 画面 | URL |
|---|---|
| 村 | `/village` |
| チャット | `/?room=1` |
| 勤怠の確認・修正申請 | `/attendance` |
| 承認（manager / admin） | `/approvals` |

**Google でログインする**（`/login`）。誰として使うかはセッションが決める。
`?me=<利用者ID>` で利用者を切り替える形は Phase 5 段階3 で廃止した。
`/village?debug=1` で開発用の切り替えが出る。

## 設定（環境変数）

| 変数 | 既定 | 意味 |
|---|---|---|
| `DATABASE_URL` | なし | Neon の接続文字列 |
| `TENKO_TZ` | `Asia/Tokyo` | 業務上の1日の境界を決めるタイムゾーン |
| `TENKO_WORK_START` | `09:00` | 始業時刻。遅刻の相対表現の基準 |
| `TENKO_LONG_WORK_HOURS` | `12` | 勤務が長いと判定する時間 |
| `TENKO_ANOMALY_DAYS` | `31` | 勤怠異常を探す期間 |
| `NEXT_PUBLIC_TENKO_IDLE_MINUTES` | `10` | 自動離席までの時間 |
| `AUTH_SECRET` | なし | Cookie とトークンの署名（`npx auth secret` で生成） |
| `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET` | なし | Google の OAuth クライアント |
| `TENKO_ADMIN_EMAILS` | なし | 最初の管理者のメールアドレス（カンマ区切り） |
| `TENKO_PUBLIC_VIEW` | `1` | 見るだけモード。`0` にすると未ログインでは村も見えない |
| `TENKO_WS_TICKET_SECRET` | なし | WSの入場券の署名鍵。**アプリと ws-server で同じ値** |
| `TENKO_WS_INTERNAL_TOKEN` | なし | ws-server → アプリの確認に使う共有秘密。**同上** |
| `TENKO_WS_VERIFY_INTERVAL_MS` | `60000` | 無効化を確認する間隔。短くできるのは確認のため |

`TENKO_DEV_USER_ID` と `TENKO_TRUST_USER_PARAM` は Phase 5 段階3 で廃止した。

## 現時点で対応していないこと

隠さずに書く。実運用の前に判断が要る。

### 深夜0時をまたぐ勤務

**未対応。** 勤怠の記録は、発生時刻の日本時間の日付でその日に入る。
出社が 8/12 23:00、退勤が 8/13 02:00 の場合、**別々の日の記録になる。**

夜勤のある職場では正しくない。直すには「勤務日」という概念（出社から退勤までを1つの勤務として束ねる）を
導入する必要があり、勤怠の記録・月次の集計・承認のすべてに影響する。
影響が広いため、現時点では未対応のままにしている。

### 認証（Phase 5。段階5まで完了）

**HTTP の経路は入った。** Google 認証（Auth.js v5）で、あらかじめ `users` に登録された人だけが使える。
セッションはDB方式で7日。利用者IDをリクエストのパラメータから受け取る形は廃止した。

**見るだけモード**（未ログインでも村が見える）。開いているのは4経路だけ:
`/api/rooms`・`/api/users`・`/api/notes`・`/api/demo-presence`。
**未ログインに返すのはデモ用の利用者の分だけ**（実在の人の表示名も「今日やること」も返さない）。
勤怠は読み取りも含めて全閉。`TENKO_PUBLIC_VIEW=0` で見るだけモードごと止められる。

**WebSocket も塞いだ（段階6）。** 村に自分を出すには入場券が要る。
券は同一オリジンの `POST /api/ws-ticket`（認証必須）で取り、
`Sec-WebSocket-Protocol` に載せて渡す。有効期限60秒・使い捨て。
**利用者IDは券から取る**ので、他人の在席を偽装できない。
券の無い接続は「見るだけ」で、送ってきたメッセージは種別を問わず捨てる。
無効化されたセッションは、60秒ごとの確認で検出して切る。

**残っている前提:**

- 券がまだ使われていない60秒の間に盗まれれば、その人として入れる（持参人式の券の性質）。
  盗める経路が成立している時点でセッションCookieも危ないため、ここは受け入れている
- `/api/ws-verify` が10分間ずっと失敗すると、認証済みの接続を全て切って見るだけに落とす

認証は単独のフェーズとして設計する。中途半端な認証は無いより危険であるため、
部分的に入れることはしない。

なお、**在席の配信に名前は含めていない。** 画面に出る名前はすべて DB の表示名であり、
接続時の自己申告は表示に一切使っていない（騙れる名前が他人の画面に出る経路を無くしてある）。

### その他

- 自動離席の閾値（10分）は仮説であり、実運用での裏付けがない
- 村の吹き出しは全員分を出す（1行に切り詰め、重ならないよう上へ避ける）。全文はメンバー一覧で見る
- 休憩は「回数」だけを数える。復帰を検出していないため、休憩時間は出せない
