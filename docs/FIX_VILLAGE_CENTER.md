# 村の中心のずれの修正

`fix/village-center` ブランチ。噴水と道の位置のずれを直した記録。

---

## 1. 実測した現在の値（直す前）

`node scripts\measure-center.js`

```
村: 40x26 タイル = 640x416 ドット / 中心 (320,208)

噴水: 左上 (304,192) 大きさ 32x32 / 中心 (320,208)
  村の中心とのずれ: (0, 0)

縦の道: x = 320..336（幅 16） 中心 328
  村の中心とのずれ: 8
  左の草地 320 ドット / 右の草地 304 ドット / 差 16

横の道: y = 208..224（幅 16） 中心 216
  村の中心とのずれ: 8
  上の草地 208 ドット / 下の草地 192 ドット / 差 16
```

PNG に描き出して画素を数えた結果も同じ（`node scripts\verify-center-png.js`）。

```
縦の道: x = 320..336 / 中心 328 / 村の中心とのずれ 8
横の道: y = 195..237 / 中心 216 / 村の中心とのずれ 8
噴水:   中心 (320,208) / 村の中心とのずれ (0,0)
```

## 2. ずれがあったか

**ありました。ただし、ずれていたのは噴水ではなく道です。**

- **噴水は村の中心 (320,208) とドット単位で完全に一致していた**（ずれ 0）
- **縦の道・横の道が、それぞれ 8ドット（半タイル）ずれていた**

原因は指示にあったとおり、タイル数が偶数であることによる。
村は 40×26 タイルなので、村の中心 (320,208) は**タイルの境界の上**にある。
道をタイル単位（1タイル幅）で置くと、その中心は必ずタイルの真ん中に来るため、半タイル分ずれる。

POが画面で見た「右が広い」という向きは、実装の値とは逆だった
（実測では左の草地 320 / 右 304 で、**左が16ドット広い**）。
画面上の目測は拡大率1.95倍と縁の描き方が混ざるため、実装の値を正とした。
**ずれが存在したという指摘自体は正しい。**

## 3. 何をどう変えたか

**道の幅は変えず、描く位置だけを8ドットずらした。**

- `src/village/map.json` に `roadShift: -8` を追加（道だけをドット単位でずらす量）
- `src/village/render.ts` の `drawGround` で、道と道の縁を描くときにこの値を足す
  - 縦の道は x だけ、横の道は y だけずらす

### 他の案を採らなかった理由

| 案 | 採らなかった理由 |
|---|---|
| 道の幅を奇数タイルにする | **この村では中心が合わない。** 村の中心がタイルの境界にあるため、タイル単位で中心を合わせるには**偶数**タイル幅が要る。奇数だとタイルの真ん中が中心になり、境界とは半タイルずれる |
| 道の幅を2タイル（32ドット）にする | 中心は合うが、道の太さが倍になり、村の見た目が大きく変わる。今回は「軽微な修正」であり、見た目を変える判断はPOのものと考えた |
| 噴水を動かす | **噴水は既に中心と一致している。** 動かすと逆にずれる |

### タイルの継ぎ目が崩れないこと

草地は先に村全体を塗ってからその上に道を描くため、道をずらしても隙間はできない。
また、縦の道は x だけ・横の道は y だけをずらすので、
もう一方の軸（道が伸びる方向）のタイルの繰り返しは崩れない。

## 4. 確認方法と結果

### PNG の画素で確認（`node scripts\verify-center-png.js`）

本番の描画コード（`render.ts` をコンパイルしたもの）で地面を描き、
「その列（行）が道の色でどれだけ埋まっているか」を数えて道の帯を出した。
道と同じ色は柵や木箱にも使われているため、1行だけを見る方法では装飾と区別できず、
列ごとの埋まり具合で判定している。

```
村: 640x416 / 中心 (320,208)

縦の道: x = 312..328 / 幅 16 / 中心 320
  左の草地 312 / 右の草地 312 / 差 0
  村の中心とのずれ: 0
横の道: y = 187..229 / 幅 42 / 中心 208
  上の草地 187 / 下の草地 187 / 差 0
  村の中心とのずれ: 0

噴水: 左上 (304,192) / 中心 (320,208) / 村の中心とのずれ (0,0)

判定: 道の中心・噴水の中心・村の中心がすべて一致
```

（横の道の幅42は、道の色が縁のスプライトにも使われているため。中心は一致している）

| 確認項目 | 結果 |
|---|---|
| 噴水の中心と村の中心が一致するか | **一致（320,208）** |
| 縦の道の左右の草地の幅 | **312 / 312（差 0）** |
| 横の道の上下の草地の高さ | **187 / 187（差 0）** |

### ブラウザでの確認

`http://localhost:3000/?me=1` を開き、噴水が交差点の中心に収まっていることを目視した。
道は左右・上下とも同じ幅に見え、違和感はない。

## 5. 装飾・建物・立ち位置に影響がないこと

### 地面のPNGを直す前後で1画素ずつ比べた（`node scripts\diff-ground.js`）

```
大きさ: 640x416（266240 画素）
道の帯（縁を含む）: x 296..352 / y 184..240
違う画素: 23044
そのうち道の帯の外: 0（＝道の外は1画素も変わっていない）
```

**変わったのは道の帯の中だけ。** 装飾（257個）が描かれている場所は1画素も変わっていない。

### 地図データの突き合わせ

```
変わっていない: width / height / tile / fountain / plaza
変わっていない: buildingSlots（26件） / plazaSpots（24件） / deco（257件）
追加されたキー: roadShift
roads: 前={"h":[13],"v":[20]} 後={"h":[13],"v":[20]}
```

建物の枠・広場・立ち位置の候補・装飾の座標はすべて元のまま。
足したのは `roadShift` の1つだけで、これは道の描画位置にしか使っていない。

なお、道の帯と重なる装飾・建物は直す前から0件で、道を動かしても新たに重なっていない
（`measure-center.js` の出力で確認）。
