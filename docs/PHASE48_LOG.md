# PHASE48_LOG

tenko Phase 4.8（移動・会議室・呼びかけ・UIの作り込み）の作業ログ。

## 設計方針の変更（この回で入れ替わったもの）

| これまで | これから |
|---|---|
| 状態が位置を決める（「会議中」を選ぶと建物に移動） | **位置が状態を決める**（建物に入ると会議中になる） |
| 自由移動は実装しない（Phase 2 の判断） | **ドラッグで自由に動ける**（POの判断で覆した） |
| 通話は将来「近づくと聞こえる」形を想定 | **近接音声は採用しない。呼びかけ→承認→通話の形にする**（POの判断） |

「会議中」は状態のメニューから外した。選ぶものではなく、位置の結果になったため。
メニューに残るのは 在席 / 離席 / 休憩中 / 退勤 の4つで、Phase 3 の勤怠検出（出社・退勤・休憩・遅刻）と対応する。

### 移動をどこで判定するか

判定は **ws-server** に置いた。理由は、画面側だけに置くと WebSocket を直接叩かれた時点で通ってしまうため。

なりすまし対策の作りは次のとおり。

- `presence.move` は **利用者IDを持たない**。`{ type, x, y }` だけ
- サーバーは、そのメッセージが届いた **WebSocket接続に紐づく人** にしか適用しない
- したがって「他人のアバターを動かす」メッセージは、そもそも表現できない

### 移動の同期頻度（作業1の判断）

| 決めたこと | 値 | 理由 |
|---|---|---|
| 画面 → サーバー | 100ms に1回まで + 離した瞬間は必ず送る | 毎フレーム送ると1人あたり毎秒60件になる。離した1件が間引きで落ちると位置がずれるため、確定は別に送る |
| サーバー → 全員 | 50ms にまとめて1回 | 人が増えても配信回数が増えない形にする。20人が同時に動いても毎秒20回で頭打ち |

タッチ操作は Pointer Events を使ったため、指でのドラッグもそのまま動く。
ただし**スマホ向けの画面の作りは想定外のまま**とする（村の横幅が640ドットあり、
携帯の画面では村全体が入らない。作り込むなら別の課題になる）。

### ドラッグ中の見た目（作業1の判断）

半透明のアバターを動かす形は採らなかった。Canvas を1ドットずつ塗っているため、
移動のたびに描き直すと20人で重くなる（Phase 4.6 で実測した固まりの原因と同じ）。

代わりに、**移動先を示す破線の枠**を HTML で重ねた。掴んでいる間、元の位置の名前は薄くする。
描き直しが起きないため、人数が増えても軽い。

### 建物の中の人の描き方（作業2の判断）— 案2 を採用

24人（うち定員4の部屋に4人、定員12の広間に12人）を実際に入れて見比べた。

| | 案1: 重ねて描く | 案2: 隠して、乗せたときに出す |
|---|---|---|
| 定員4の部屋 | 建物が人物で完全に隠れる。4人が重なって1つの塊に見える | 建物が見える。満員の枠も見える |
| 定員12の広間 | 12人が潰れて誰も読めない。建物も見えない | 同上 |
| 満員かどうか | **分からない**（枠が人物の下に隠れる） | 枠がはっきり見える |
| 誰がいるか | 分からない（重なっているため） | 乗せると名前が全員出る |

**採用したのは案2。** 理由は好みではなく、寸法が成立しないため。
建物は32ドット四方で、人物も32ドットある。1人で建物が埋まる大きさなので、
定員4でも重ならずに描くことは不可能で、定員12は論外だった。

案2で失われる「一目で誰がいるか」は、建物に乗せたときの一覧で補う
（`広間 12/12 満員 / 群衆05、群衆06、…` を実測で確認）。

満員は**金色の破線枠**で示す。窓の明るさは「誰かいる」との区別が付かないため、形を変えた。

### 吹き出しの表示件数（作業4の判断）— 常時3件 + 乗せた人

25人を広場に集めて 3 / 5 / 8 件を実機で見比べた。

| 件数 | 見え方 |
|---|---|
| 8件 | 吹き出しが下の段の人物の顔にかぶる。誰の発言か分からなくなる |
| 5件 | 横につながって1本の帯に見える。個々の境目が読み取れない |
| 3件 | 上の段で触れ合うが、読めなくなるところまでは行かない |

**3件にした。** そのうえで「マウスを乗せた人の吹き出しは、上限に関係なく必ず出す」ようにした。
常時全員分を出す方向は、人数が増えるほど破綻する。見たい人のものが読めれば足りる。
全員分は「メンバー」の一覧で見られる。

### 呼びかけと「話しかけてよいか」の連動（作業3の判断）

| 相手の状態 | 動き |
|---|---|
| 話しかけてOK | そのまま呼びかけられる |
| 後でならOK | 呼びかけられる。ボタンに「（後でならOK）」と出る |
| 集中中 | **確認を挟む。** 「急ぎでなければ、あとにしてください」と出し、押した場合は相手に「集中中と分かったうえで呼んでいる」ことが伝わる |

**止めるのではなく確認にした理由**: 呼びかけを止めると、急ぎの用事のときに別の連絡手段へ逃げることになり、
結果として「集中中」を出すこと自体が避けられるようになる。
断る権利は相手に残したまま、呼ぶ側に一手間かける形にした。

確認にブラウザの `confirm` は使わない。画面が止まるうえ、村の見た目から浮くため、パネルの中で聞く。

### 呼びかけの連打を防ぐ（作業3の判断）

- 同じ相手へは5秒あける
- 全体で1分あたり10件まで

接続ごとに記録する。15回連続で送って、通ったのが0件・断られたのが15件であることを実測した。

### この周で見つけて直した不具合

## 周回2（審査）

### 審査役A: セキュリティ

`node scripts\attack-phase48.js` を実行した結果。

| 送ったもの | 結果 |
|---|---|
| 他人のアバターを移動（`user` / `userId` / `id` を添えた move を3通り） | 被害者は動かない。攻撃者自身だけが動く |
| 村の外 `(99999,99999)` | `(608,366)` に収まる |
| 負の数 `(-500,-500)` | `(0,0)` に収まる |
| 極端に大きい値 `1e18` | `(608,366)` に収まる |
| `Infinity` / `NaN` / 文字列 / `null` / 配列 | いずれも「座標が不正です」で拒否。位置は変わらない |
| 満員（4/4）の建物へ入る | 「「オフィス」は満員です（4/4）」で拒否。人数は 4/4 のまま |
| `from` を詐称した呼びかけ | 届いた `from` は `{"id":9002}`。**名前は含まれない** |
| 「社長」と名乗り直してから呼びかけ | 同じく `{"id":9002}`。自己申告の名前は届かない |
| 呼びかけを15回連続 | 通った0件 / 断られた15件 |
| `message.created` / `presence.setx` / `call` / `admin.grant` / `rooms.update` | 何も返らない（捨てられている） |
| `POST/PUT/PATCH` を `/api/presence` `/api/rooms` `/api/village/move` へ | 404か405のみ。定員は 4 のまま変わらない |

**この周で見つけて直した穴**: 呼びかけの通知に自己申告の名前が入っていた（上の表の「周回1で見つけて直した不具合」に記載）。
直す前は、`presence.set` で「社長」と名乗れば、相手の画面に「社長さんが呼びかけています」と出た。
