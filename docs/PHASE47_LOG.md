### 3. アバターの大きさをどう決めたか

16ドットのままでは、足元のリングを引く余地も、名前を読める大きさで置く余地もありませんでした。
ドット絵は整数倍でしか綺麗に拡大できないため、選べるのは2倍か3倍です。
広場に20人並べたときの右端・下端を実測しました（村は 640x416）。

| 倍率 | 人物の大きさ | 右端 | 下端 |
|---|---|---|---|
| 2倍 | 32px | 580 / 640 収まる | 372 / 416 収まる |
| 3倍 | 48px | 708 / 640 **はみ出す** | 420 / 416 **はみ出す** |

3倍は20人で村の外に出るため、2倍を採りました。
oVice が1.6倍にしているのは同じ理由（表情が見やすくなる）で、方向は一致しています。

### 4. 他人のアバターを押したとき（実機で確認）

情報だけが出ます。状態・話しかけ可否・今日やることが読めるだけで、変更する操作は1つもありません。
末尾に「他の人の状態は変えられません。」と書いてあります。

API側でも拒否されることを実測しました（`node scripts\attack-presence.js`）:

- `POST /api/presence` → 404、`POST /api/attendance/presence` → 404。**他人の在席を変える口自体が存在しません。**
- WS の許可リストにない種別（`message.created` / `call.offer` / `admin.grant` / `presence.setx`）は捨てられ、`messages` は 10 件のまま増えませんでした。

**ただし、WS の `presence.set` は他人のIDを名乗れます**（認証が未実装のため。S6 の既知の状態）。
そのため村に出る**名前は DB の表示名を使う**ようにしてあります。
実測では、攻撃側が「乗っ取り」と名乗っても DB の表示名は「群衆01」のままで、画面には「群衆01」が出ます。
